## 有限候选集的证书

对每个Joint方案P，dominance_certificate.csv给出一个属于固定划分的方案Q：

```
max_i peak_i(Q) <= max_i peak_i(P)
C_model(Q) <= C_model(P)
```

384/384项成立。因此任意共同容量只要允许P，就允许一个成本不高于P的Q。固定划分空间又是Joint空间的子集，所以两个参考最小成本在所有正共同容量上相同；不是只扫了几个容量点后没找到。

峰值是当前模型的逻辑显存预测，候选融合含planned模式；证书不代表正式融合执行能力或GPU物理时间。负结果只覆盖本图、本候选集和本Profile，不构成同构设备的一般可分离定理。

## 设备对称口径

本轮实际使用AnalyticHardwareProfile（tools/evaluate_mcts_budget_controls.py:53），不是旧E0按model:bw池化的实测Key。硬件快照两卡算力约94.504/94.440TFLOPS，也没有完全相等。

即使Kernel时延相同，改变放置仍会改变跨卡边、设备队列和排程（structural.py:196–268）。现有serial_tail只有一种singleton划分，1024种放置的预测成本仍从102.956到645.792μs；不能由设备近对称推出“固定划分后换设备几乎不改总成本”。

同构且无容量约束也不自动保证融合/放置可分离。例如纯数学图A→C、B→C，两个同速设备，A=B=8、C=1，融合AC耗时8.5，跨卡传输0.1：单卡顺序评价会选融合（16.5<17），而两卡未融合可并行A/B，成本9.1，融合组则至少16.5。该反例只说明一般推理缺少条件，不作为项目任务或收益数据，也未写入Profile。

原90%对照本身已经容量绑定；不能把那批结论改写为“容量不绑定的中等图”。当前工程能力仍是融合感知评估、合法图搜索及设备/融合约束输出；“Joint优于Sequential”的科研收益尚未验证，不作为已成立贡献。
