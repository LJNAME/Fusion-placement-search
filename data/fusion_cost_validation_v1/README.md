## 数据与适用范围

输入是 `silu-mul-additivity-20261101` 四臂批，SiLU / Mul / SiLU→Mul 链 / KERV 融合。双卡、seq=1/256、宽度3072、bf16；每 case 8配对轮×4臂×50调用。十份原始文件逐字节复制到 `inputs/`，源码、硬件和输入 hash 见 `plan.json`。

测量契约 `sha256:b0b0cd8a76c3bbe3d4924d718cc4d84807043c2c7643fdc12a7324a501f49c48`：graph replay、50次批次摊销、throughput_per_call、serial_plan_only。数字是此工作集与图重放条件下的每调用摊销时间，不是单次延迟或分离出的纯核时间。不能与 eager 数字相减得到提交成本，也不能直接宣称代表下游编译执行。

所有标签仍为 `conditional_dev`。本模板使用显式诊断开关和共享标签闸门，返回警告、低置信度与 OOD；默认拒绝。`diagnostic_arm:*` 仅为局部夹具身份，不是生产 canonical Kernel Key，不改旧 Key、不导出 accepted 标签。正式能力范围仅层内，当前开发 registry 仍不构成部署准入。

## 搜索端检查

每 case 构建4节点局部图（两个逻辑输入、SiLU、Mul），固定到对应实测卡，只比较融合/未融合。两种 Profile 分别跑 Exact 与 MCTS（16迭代、3 rollout、seed23），共8次 MCTS、8次局部 Exact；不是整 MLP、放置或联合搜索实验。

搜索只拿 silu / mul / fused 三个标量，链时间只作独立评价参考。实测 duration 仅消费一次，新增 launch=0。解析回退仍沿用原硬件快照；没有用总摊销时间反推 launch。

8次 MCTS 都达到对应局部 Exact 最低成本，四点解析版与条件标签版均选融合，真实输出翻转0。8份输出在 `artifacts/`，均 `deployable=false`。人为慢融合的单测能触发不融合分支，但它是合成接口回归，不是实测反例。

## 解析模型比较的限制

`cost_model/hardware_profile.py:109–113` 使用组外部流量与 launch/fusion 常数；内部流量、具体实现效率等仍是近似。已有 `KeyedKernelProfile` 可按组身份覆盖实测 duration（`fusion_kernel_profile.py:153/221`），不应描述成完全无法表示融合实现差异。

当前硬件 launch=7.770405267 μs，未按本 graph 契约重新标定。四点旧解析融合估计高于测量38.13%–120.14%，记为迁移先验误差，不能单独归因于理想融合或实现开销。契约一致解析基线仍待建立；当前未隔离实现误差，也未证明理想假设成立。

合法性与收益应分别检查。但局部组流量近似并不能推出任意整图合法融合必然降低 makespan；并行性、放置、通信和容量还会改变整体评价。eager 与 graph 的方向不同也不等于同契约下的形状反转。

## 后续固定流程

1. 正式文件到位后，列出允许的层内 pattern、实现版本、shape/dtype/layout/别名守卫；在看新标签之前固定每 pattern 2–3 个形状及全部报告规则。
2. 先声明目标执行/测量契约和 duration/launch/fusion 的计费边界；契约不确认则保留条件开发态。旧 launch 不自动迁移，36条旧标签不自动升格。
3. 同批测融合、未融合联合链及必要的单核臂，记录正确性、配对轮、漂移、离散度、失败。不同契约/批次不混成一对；小于噪声或偏好带的差异记不定。
4. 分别报告契约一致预测误差、同契约融合盈亏、加性误差。链标签不作为可揭示 Kernel 标签，不用评价器隐藏数据更新搜索。
5. 仅替换允许的组代价，保持图/硬件/能力/约束/MCTS配置固定，比较输出划分、设备、可行性和参考代价；不要求实现整图执行或下游配置。

所有样本更快，只能支持已测区域；一个更慢样本可暴露模型失配，但不能自动构成论文贡献。进一步研究仍需明确机制、对照模型和代表性验证，不能仅凭四点决定换课题。

重放中的 observed_search_wall_s 是观测值，不要求逐字节一致；不将其用作新搜索性能基准。当前结论为工作流回归，不是实测纠错、SROP收益或融合近似的普遍证伪。
