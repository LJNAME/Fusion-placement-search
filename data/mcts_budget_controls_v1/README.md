## 预算控制的含义

| 对照 | seed23成本，J / S μs | J−S μs |
|---|---|---:|
| J8 vs S16(8+8) | 329.644936 / 329.649614 | −0.004678 |
| J16 vs S16(8+8) | 282.100895 / 329.649614 | −47.548719 |
| J16 vs S32(16+16) | 282.100895 / 271.964004 | +10.136891 |
| J32 vs S32(16+16) | 271.984553 / 271.964004 | +0.020550 |

前两seed在这些配对中的输出成本都相同。总预算32时S没有保留>10%的差距；J8与S16的逐seed差距也接近。默认总预算16下的差异是真实记录，但不足以归因为提前承诺。

全部S16/S32运行冻结同一划分，其Exact最优成本等于Joint全空间最优，划分承诺的可达参考损失为0。本例没有“冻结划分排除了更优解”的证据，也不支持“提前冻结显著拖慢收敛”的归因。结果更符合当前对半分配把放置阶段预算减半的解释。

不能据此宣布两种方法普遍具有相同收敛速度或都收敛到同一计划。总预算16的默认实现仍有质量差异，32时的成本接近也不表示所有计划签名相同；只有3个已暴露开发seed。

## 数据与复核

- results.csv：21条逐seed结果，含预算拆分、参考口径、全空间差距、阶段评分/模型评估数及观测墙钟。
- runs.jsonl：9条新运行与12条原样复用记录，origin区分来源；保留完整输出计划和阶段信息。
- new_candidates.csv.gz / new_requests.csv.gz：9条新运行的完整评分记录。候选run_id就是control_id。
- report.json：一个共同冻结划分、相对全空间参考损失为0，输入与算法未改变。
- verification.json：9条新运行、12条复用记录、311个不重复候选/560次请求复核通过；逐阶段预算与引用差距、严格可行最小返回一致。
