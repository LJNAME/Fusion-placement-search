# 分支感知与混合 Joint：中等子图对照

2026-11-09。继续使用stage_search_medium_v1的三个3B中等子图、两个容量场景、blocking HTAE和原成本参数。未运行完整3B、未新增GPU测量。

## 四种动作

| placement_policy | 设备选择 |
| --- | --- |
| node | 原逐节点／融合组独立选卡 |
| contiguous_stages | 固定拓扑顺序上的连续阶段，每卡最多使用一次 |
| branch_aware | DAG自动识别分叉→独立线性通路→同一汇合；每条通路内部同卡，其他节点独立选卡 |
| hybrid | 分支通路独立选卡，其余串行主干使用连续阶段；跨分支与主干的融合必须同时满足两种约束 |

分支检测不读取MLP、Gate或Up名称。只接受内部不再分叉、互不重叠并汇合到同一节点的简单通路；嵌套或部分汇合不强行合并。没有识别出分支时，branch_aware退化为node，hybrid退化为contiguous_stages。混合模式是一个方案内部组合两种约束，不是把两个搜索结果事后取最小；它也不保证包含原阶段空间的全部方案。

MLP识别到pre_mlp_norm→{gate_proj→silu, up_proj}→gated_mul。融合仍由搜索器选择；若SiLU与Mul融合，该组必须与Gate分支的已绑定设备兼容，不能绕过融合同卡条件。

## 预算与统计

- 每种方法最多64次独立完整方案实际模型调用，种子0／7／23；两卡未融合初始化、不可行候选都计费，重复查询只命中本次缓存。
- 4种方法共用相同UCT归一化、耗尽子树处理、3次rollout及融合概率0.7。没有注入Exact方案，没有使用额外热身方案。
- Exact独立穷举原空间；三个受限动作空间另行穷举，区分空间限制损失与搜索误差。少于64项的空间枚举完停止，报告未使用预算，不凑次数。
- 6任务×4方法×3种子＝72次运行。serial_tail cap75、attention_fork cap75原空间Exact均无可行解，照常保留，不计算Gap。
- cap75沿用单卡前向峰值75%的合成预算；不代表训练预算或物理显存75%。边界驻留沿用既有提取器的自由放置声明。

分支并行度由本次已计费HTAE时间线计算，不额外预测：不同分支通路在不同卡上同时执行的时间记为branch_overlap_us，其占makespan的比例另存。最大分支并行设备数0表示没有识别到的分支工作，1表示执行过分支但没有跨卡同时执行，2表示观察到双卡分支重叠。只把两个GPU都用过不算并行。

## 融合—放置耦合

离线使用原空间Exact的完整标签，对同一组逐节点设备分配比较Native与Fused。对手不可见这些标签；不把分析调用算入搜索预算。数值比较容差固定为1e-9 ms，仅用于浮点比较，不是性能显著性阈值。

分开记录：合法放置集合是否改变；Δ(P)=T(Fused,P)−T(Native,P)是否随P变化；是否存在融合偏好翻转；共享可行域上最优放置集合是否不相交；两个放置在Native与Fused下是否发生排序反转。每种交互都有完整放置和两臂成本见证。

| 子图／场景 | 共同可行放置数 | Δ范围 | 融合偏好翻转 | 最优放置变化（共同域） |
| --- | ---: | --- | --- | --- |
| serial_tail free | 512 | −9.334363～−9.333616μs | 无，始终Fused更快 | 无 |
| mlp free | 128 | +12.697285～+28.878480μs | 无，始终Native更快 | 无 |
| mlp cap75 | 96 | +12.697285～+28.878480μs | 无，始终Native更快 | 无 |

attention_fork没有融合替代项，记为不适用；不可行容量任务没有可比较的共同可行域。

MLP有16.181194μs的数值成本交互，也有部分放置排序反转；但没有观察到融合偏好翻转或共同域上最优放置集合改变。serial_tail的Δ波动仅0.000747μs，不据此宣称有实际优化意义。当前结果支持“分支感知动作保住更好的放置”，尚不支持“联合搜索已获得不可替代的融合—放置决策收益”。这些均为当前评分模型的反事实结果，不是GPU实测性能结论。
