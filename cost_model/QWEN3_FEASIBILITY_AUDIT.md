## 失败原因

### 容量下界

当前 `_stage_devices` 要求主干阶段不能返回旧卡；embedding与最后的lm_head绑定同卡，使整个主干都留在embedding所在卡。这个约束属于当前混合动作空间，不是物理硬件要求。

| 必须驻留的内容 | 字节数 |
| --- | ---: |
| 主干参数 | 839,778,304 |
| 末端lm_head输出 | 77,791,232 |
| 合计下界 | 917,569,536 |
| 剩余参数空间 | 35,241,984 |
| 每个MLP分支单元参数 | 6,291,456 |

56个分支单元中，至多5个可留在主干卡，至少51个必须外放；这是必要条件，不是完整峰值显存的充分条件。第6个分支留在主干卡时，下界变为955,318,272 B，已经超过预算。

SiLU×Mul包含主干上的join与gate分支上的SiLU，融合后同卡要求及分支绑定会把gate projection也锁在主干卡。默认倾向融合、倾向保持最近设备的补全没有考虑这条容量约束。因此，大量完整rollout在评分之前就已可证明超限。

### 搜索树与补全

对三个种子的“共同witness＋原始搜索”逐项记录选中的部分状态及完整rollout，成本、预算与原实验一致。

| 检查 | 结果 |
| --- | --- |
| witness能否由混合树表达 | 能，591动作回放通过 |
| 新实验共享权重违规方案 | 0/1,536，全部通过完整融合合法性与共享参数检查 |
| 原混合Joint选中树前缀最大深度 | 三种子均16 |
| 这些前缀已绑定的MLP分支数 | 均为0 |
| 来自“下界已证明无解树前缀”的rollout | 0 |
| 每种子后续完成的不可行候选 | 61/61，都可由下界提前拒绝 |
| 首条必然超限的补全前缀 | 第56动作，62节点已分配；L002.mlp.up_proj成为第6个本卡分支 |

观测到的失败主要发生在rollout，而不是树已经深入不可行的分支。下界没有证明选中的树前缀无解，不把这一点夸大为所有前缀均有完整可行补全。

主干不可返回确实排除了合法的半层切分参考：共享head必须返回embedding卡，而当前主干禁止返回。旧参考在 `L014.input` 被拒绝的记录保留于 `data/full_joint_models_v1/hybrid_feasibility_diagnostic.json`。本轮不放松动作域，以免将空间变化混入可行性机制对照。

## 最小改动

- 新增 `cost_model/forward_feasibility.py::ForwardResidentBound`：使用当前前向内存模型的参数常驻项，加上必定同卡的末端输出；混合域额外计入已绑定分支与被迫驻留的主干。
- `LegalFusionSearchSpace(partial_prune=...)` 在生成动作时过滤已证明超限的部分状态，树扩展及随机／确定性rollout共用，默认None。
- `legal_mcts_search` 透传该可选约束，增加不评分的rollout观察接口，并处理剪枝后没有补全的状态；UCT、Q回传及融合概率不变。
- 保留共同witness作为外部incumbent，所有方法在第3次评分获得同一方案；不把witness的分数注入树Q。
- 过滤不调用HTAE或任何耗时预测，只计算字节下界；完整候选仍由原模型独立检查峰值。该机制没有声称物理allocator、训练状态或所有激活均被下界覆盖。

## 同预算对照

每次64个不同完整方案实际评分：前两次为两卡Native，第3次为共同witness，余61次为搜索。三个种子0/7/23，四种方法，两种机制，共24运行／1,536次评分。另有一次独立见证CPU校验。所有方法都获得同一初始先验；没有增加评分预算或调用全图Exact标签。

下表为三个种子的中位数。后续可行数不含前三次初始化。

| 方法 | 仅共同witness：后续可行／61 | 仅共同witness：最佳ms | witness＋过滤：后续可行／61 | witness＋过滤：最佳ms |
| --- | ---: | ---: | ---: | ---: |
| 原始逐节点Joint | 60 | 10.240171 | 61 | 10.240171 |
| 混合Joint | 0 | 15.879727 | 61 | 15.132347 |
| Random原空间 | 61 | 15.879727 | 61 | 15.879727 |
| Random混合空间 | 0 | 15.879727 | 61 | 15.132019 |

- 仅加入witness就能让所有运行返回可行方案，但两个混合方法后续仍没有发现新的可行候选，不能将兜底成功归因于搜索改进。
- 同先验下，过滤使两个混合方法的后续可行数均由0/61变为61/61；最佳方案跨卡边中位数由112降为102。
- 混合Joint只在1/3种子优于同域Random，未证明MCTS稳定优势。
- 原始逐节点Joint仍优于两个混合方法。过滤解决了当前可行性发现问题，没有解决混合空间因主干绑定造成的方案质量损失。
- 下界检查增加CPU开销；逐运行墙钟和拒绝次数全部保存，不声称搜索墙钟加速。

旧无witness的12运行仍保留于 `data/full_joint_models_v1/qwen3_06b/`，作为历史对照。新“仅witness”12运行去掉第3项后，剩余63项与旧实验前63项的候选ID、评分、显存和可行性完全一致；不将更换先验或少一次后续评分伪装成算法收益。
